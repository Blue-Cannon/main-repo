# Security Policy

## Our Organization
GitHub Organization based in Teachers Camp, Baguio City, Philippines.
We handle reports about: Secret Leak, Critical Bug, Unauthorized Access,
Data Breach, Phishing Link, Fake Account, and Malware.

## How to Report a Vulnerability

**DO NOT post the vulnerability in public Issues, Discussions, or public chat.**

Posting a secret or bug in public will make the leak WORSE.

### Please use:
1. Go to this Repo > **Security** tab > **Report a vulnerability**
2. Describe what you found:
   - What type? Secret Leak / Bug / Unauthorized Access / Data Breach / Phishing / Fake Account / Malware
   - Where? File name, line, commit link
   - How did you find it?
   - Do NOT paste the full secret key. Mask it like: `sk-****1234`
3. Submit privately.

## What Happens After You Report?

1. **We check** - Our team checks if the report is REAL or NOT.
   The machine does NOT auto-detect. A human will verify.
2. **We verify** - We check the repo, reproduce the bug, check if the secret is real.
3. **We alert staff** - If REAL, we send an internal Security Alert (EAS) to staff only.
   Staff will fix it: remove secret, rotate key, fix bug, secure repo.
4. **We fix** - Staff fixes in private.
5. **We update you** - We tell you when it's fixed. Thank you!

We will respond within **48 hours** if the report is real.

## What NOT To Do

- DO NOT post secrets, passwords, API keys in public.
- DO NOT test the vulnerability on other members.
- DO NOT send a fake report to test us. Fake reports will be closed.
- DO NOT share the private report with others.

## EAS Alert Process

When a report is verified as REAL:
- We send an internal Security Alert to staff only.
- The alert is NOT broadcast to public TV / Radio.
- It is only for our organization members.

## Contact

For urgent issues, contact the maintainers through GitHub Private Vulnerability Reporting only.

Thank you for keeping our organization safe!
